# FE-03. Incidents — реестр и локальная фильтрация

**Приоритет:** P0 · **Исполнитель:** Frontend · **Зависимости:** FE-01, модель инцидента из FE-02 (если уже слита) · **Статус:** TODO.

**Figma:** https://www.figma.com/design/JFUcynM2y9vIq6vJ7efTOc?node-id=6-26

## Цель

Создать профессиональный табличный реестр инцидентов, позволяющий быстро найти запись, отфильтровать и перейти в детали.

## Объём работ

1. Страница `/incidents`: заголовок `Incidents`, контекстная подпись и кнопка `+ New investigation`.
2. Панель фильтров в порядке Figma: текстовый search `ID / service / title`, severity, status, project, time range.
3. Компактная таблица с колонками `ID / Title`, `Service`, `Severity`, `Status`, `Detected` (сохранять точную структуру и proportions из Figma при достаточной ширине).
4. Реализовать **комбинируемые** локальные фильтры и регистронезависимый поиск. Пустые фильтры не ограничивают данные, одновременно выбранные применяются логическим AND.
5. Сортировка по времени обнаружения; значения времени — единый timestamp в typed mock data и понятный UI format с timezone.
6. Предусмотреть сброс всех фильтров, число найденных записей, empty result и empty dataset.
7. Нажатие на строку либо ссылку ID открывает `/incidents/:incidentId`, без сброса основной навигации. Не ломать nested интерактивные элементы таблицы.
8. `+ New investigation`: только демонстрационное действие или disabled с пояснением, никакого реального запуска. Если mock dialog создан — обозначить `Demo / Not connected`, не сообщать об успешном запуске AI.
9. Mobile: фильтры складываются, таблица остаётся доступной (локальный horizontal scroll, не обрезание целых столбцов). Keyboard focus и подписи форм обязательны.

## Тестовые случаи

- `INC-1042` находится при `inc-1042` и `PAYMENT` (независимые проверки).
- `Critical + Investigating` возвращает ожидаемые записи; фильтры совместно не расширяют результат.
- `No matching incident` выдаёт понятный empty state, reset возвращает весь набор.
- Сортировка сохраняет ожидаемый порядок timestamps (не по отображаемой строке).
- Клик по ID сохраняет correct incident route.

## Не входит

Backend search/pagination, экспорт CSV, realtime alerts, CRUD-инцидентов, неутверждённые операции над расследованием.

## Предполагаемые зоны файлов

`src/pages/incidents/*`, `src/features/incident-filters/*`, shared `DataTable`, `src/mocks/incidents*`, tests.

## Anti-AI-slop design directive

Реестр — **таблица, а не бесконечный каталог карточек**. Не добавлять иконку к каждой записи, огромные цветные плашки, светящиеся границы, жирный hero. Метки severity компактные, status понятен словами. Моноширинные ID/timestamps, predictable column widths, тонкие separators; соблюдать [DESIGN_QUALITY_GATE.md](./DESIGN_QUALITY_GATE.md).

## Критерии приёмки

1. Таблица в соответствии с Figma 6:26; минимум 7 демо-записей со согласованными ID.
2. Search, severity, status, project, time range и сортировка реально работают.
3. Фильтры комбинируются; reset и empty states корректны.
4. Переход по `INC-1042` открывает страницу выбранного инцидента.
5. Состояния loading/error/empty/long text отображаются корректно.
6. Keyboard/focus/mobile поведение проверено.
7. Unit tests фильтрации и сортировки проходят; typecheck/lint/build проходят.

## Выходной контракт

Полностью работающий на mock-данных реестр с демонстрацией 5 сценариев фильтрации, скриншотами 1440 и 390 px, тестами и ссылкой в PR на FE-03.
